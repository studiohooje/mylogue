## 0. 한눈에 결론

### 연동

| 구분 | 대상 | 한 줄 |
|---|---|---|
| **지금 가능**(무료·승인 없음) | **Android Health Connect 읽기** | 삼성 헬스·Zepp·Withings·Fitbit 등이 Health Connect에 쓴 체중·체지방·걸음·운동·수면을 Capacitor 플러그인으로 한 번에 받는 길. Play 밖 APK 배포라 Play 심사도 아직 해당 없음. **가장 먼저 할 일** |
| 지금 가능 | **파일 가져오기**: Apple 건강 내보내기(XML), 삼성 헬스 개인정보 내려받기(CSV), 가민·폴라·코로스·Strava의 FIT·GPX·TCX | 서버 없이 기기 안에서 읽음. 자주 쓰긴 어렵지만 '처음 옮겨 오기'에 좋음 |
| 지금 가능 | **iPhone 단축어 → 붙여넣기** | PWA는 HealthKit을 못 읽는다. 사용자가 단축어를 한 번 설치하면 체중 등을 글로 만들어 마이로그 붙여넣기 칸으로 |
| 지금 가능 | **사진 OCR**(인바디 결과지·앱 화면) | 이미 있는 기능. Health Connect에 **골격근량이 없어서** 인바디는 계속 이 길이 주력 |
| 신청·서버 있으면 가능 | Withings·Polar(무료 OAuth), 가민 개인 키(본인만) | 모두 **비밀키 교환 서버**가 필요. 지금 Firebase 무료 요금제 구조로는 어려움 |
| 신청해도 어려움 | 삼성 헬스 Data SDK, 가민 사업자 API, Coros·Suunto 파트너, Google Health API(Fitbit 후속) | 파트너 심사·회사 요건·보안 심사. 소규모 베타 단계에선 비현실적 |
| 사실상 불가 | 인바디 LookinBody API(유료 B2B), iPhone PWA에서 HealthKit 직접 읽기, 캐시워크·토스 만보기 | 공개 경로 없음 |

### 직접 입력 편의성 (덧붙일 것)
- **한 손 아래쪽 입력**, **앱 아이콘 길게 누르기 바로가기 + 홈 위젯**, **공유하기 확장**(사진·파일·배달 주문 글), **음성은 키보드 마이크부터**, **바코드는 '한 번 등록하면 다음부터 바로'**, **운동 중 한 손 세트 기록**, **휴지통과 변경 내역**, **알림 대신 '보이는 곳'에 두기**.

# 1부. 웨어러블·건강 앱 연동

## 1-1. 지금 마이로그 구조와 제약 [코드]

- Android 앱: Capacitor 8, `minSdk 24`, 플러그인은 Firebase 로그인·로컬 알림뿐(`app/package.json`). 권한은 인터넷·위치뿐.
- **공유 받기는 이미 있다**: 다른 앱에서 '공유 → 마이로그'로 **글**(text/plain)을 받으면 웹 화면에 넘긴다(`MainActivity.java` `deliverShare`). PWA도 `share_target`(GET, 글만)이 있다(`manifest.webmanifest`).
- 인바디 결과지 사진 OCR(tesseract, 한국어 데이터) 있음(`inbody-photo.js`).
- iPhone은 PWA만(대표님 결정). Firebase는 무료 요금제(Spark), 앱 안에 서버 코드 없음.
- 배포는 Play 스토어가 아니라 **웹에서 APK 직접 설치**.

→ 이 구조에서 **서버 없이, 기기 안에서** 읽을 수 있는 길이 1순위다.

## 1-2. 대상별 정리

### Android Health Connect — 1순위

| 항목 | 내용 |
|---|---|
| 무엇 | Android의 기기 안 건강 데이터 저장소. 삼성 헬스·Fitbit·Zepp·Withings 등 여러 앱이 쓰고 읽는 공용 창구 |
| 기기 조건 | **Android 9 이상 + Google Play 서비스**. Android 13 이하는 Play 스토어 앱, 14부터 시스템 내장 [근거: [사용 가능 여부](https://developer.android.com/health-and-fitness/health-connect/availability), [FAQ](https://d.android.com/guide/health-and-fitness/health-connect/frequently-asked-questions)]. 갤럭시 노트8(Android 9)도 대상. 마이로그 `minSdk 24`라 Android 7~8에서는 기능을 숨겨야 함 |
| 비용·승인 | API 사용은 무료. **Play에 올릴 때** '건강 앱 신고서'·데이터 보안 양식·개인정보 처리방침이 심사 대상 [근거: [Play 게시 안내](https://developer.android.com/health-and-fitness/health-connect/publish), [정책 FAQ](https://support.google.com/googleplay/android-developer/answer/12991134)]. 지금처럼 Play 밖 배포면 이 신고 절차는 해당 없음 [추정]. 다만 **권한 화면의 '개인정보 처리방침' 링크를 받을 화면(rationale activity, Android 14+는 activity-alias)을 반드시 선언**해야 함 [근거: [시작 안내](https://developer.android.com/guide/health-and-fitness/health-connect/develop/get-started)] |
| 붙이는 방법 | Capacitor 플러그인: Capawesome Health(Health Connect·HealthKit 공용, 운동 세션 읽기 포함), `@capgo/capacitor-health`(걸음·체중·체지방·수면) 등 [근거: [Capawesome](https://capawesome.io/docs/sdks/capacitor/health/), [Capgo README](https://cdn.jsdelivr.net/npm/@capgo/capacitor-health@8.7.0/README.md)]. 라이선스·유지 상태는 [확인 필요] |
| 오는 데이터 | 체중(`WeightRecord`), 체지방률(`BodyFatRecord`), 제지방량(`LeanBodyMassRecord`), 운동 세션(`ExerciseSessionRecord`), 걸음, 심박, 수면(`SleepSessionRecord`), 영양(`NutritionRecord`) 등 [근거: [데이터 유형](https://developer.android.com/health-and-fitness/health-connect/data-types), [레코드 목록](https://developer.android.com/reference/kotlin/androidx/health/connect/client/records/package-summary)] |
| **없는 것** | **골격근량 유형이 없다** [근거: 위 목록에 없음, [삼성 개발자 포럼](https://forum.developer.samsung.com/t/health-connect/27516)]. 웨이트 세트(무게×횟수)는 운동 세션에 거의 안 담김 [추정] |
| 기간 제한 | 기본은 **권한을 처음 준 때부터 30일 전까지**만 읽힘. 더 옛날은 `READ_HEALTH_DATA_HISTORY` 권한 추가, 백그라운드 읽기도 별도 권한 [근거: [읽기 안내](https://developer.android.com/guide/health-and-fitness/health-connect/develop/read-data), [블로그](https://android-developers.googleblog.com/2025/03/health-connect-jetpack-sdk-now-in-beta.html)] |
| 위험 | Play 밖 앱에서 권한 화면이 안 뜬 사례(커스텀 OS) 보고 [근거: [GrapheneOS 포럼](https://discuss.grapheneos.org/d/26322-sideloaded-app-fails-to-launch-health-connect-permission)] → **갤럭시 실기기 시험이 첫 단계** |

### Samsung Health(삼성 헬스)

- **Data SDK 직접 연동은 파트너 승인 필요**: 공개 배포 앱은 신청·승인 후 패키지명·서명을 등록해야 하고, 승인 전엔 개발자 모드에서만 동작 [근거: [앱 생성 절차](https://developer.samsung.com/health/data/process.html), [검증](https://developer.samsung.com/health/data/guide/app-verification.html)]. 옛 SDK는 2025-07-31 종료.
- **Health Connect 경유는 승인 없이**: 삼성 헬스 > 설정 > Health Connect에서 사용자가 켜면 양방향 동기화 [근거: [삼성 개발자 블로그](https://developer.samsung.com/health/blog/en/accessing-samsung-health-data-through-health-connect), [FAQ](https://developer.samsung.com/health/health-connect-faq.html)]. 삼성 고유 데이터는 안 넘어옴.
- **체성분 주의**: 갤럭시 워치 체성분을 Health Connect로 읽는 삼성 예제가 있으나 [근거: [삼성 블로그](https://developer.samsung.com/health/blog/reading-body-composition-data-with-galaxy-watch-via-health-connect-api)], 사용자 보고로는 **체지방률·골격근량이 Health Connect 쪽에 안 보이는 경우**가 있다 [근거: [삼성 커뮤니티](https://r1.community.samsung.com/t5/samsung-health/%EC%95%B3%ED%94%8C%EB%A6%AC-%EC%95%B1-%ED%97%AC%EC%8A%A4-%EC%BB%A4%EB%84%A5%ED%8A%B8-%EC%82%BC%EC%84%B1-%ED%97%AC%EC%8A%A4-%EC%97%B0%EB%8F%99-%EC%8B%9C-%EC%B2%B4%EC%A7%80%EB%B0%A9%EB%A5%A0-%EA%B3%A8%EA%B2%A9%EA%B7%BC%EB%9F%89-%EB%AF%B8%ED%91%9C%EC%8B%9C-%EB%AC%B8%EC%A0%9C-%EB%AC%B8%EC%9D%98/m-p/34106452/highlight/true)] → 체중은 기대, 체지방은 [확인 필요], 골격근량은 기대하지 않음.
- 동기화 시점이 불규칙하다는 개발자 문의도 있음 [근거: [포럼](https://forum.developer.samsung.com/t/topic/27389)].
- **파일 경로**: 삼성 헬스 '개인정보 내려받기'로 전체 기록을 받을 수 있다 [근거: [삼성 지원](https://www.samsung.com/us/support/answer/ANS10001379)]. CSV 칸 이름은 비공식 안내뿐 [확인 필요].

### Apple 건강(HealthKit)·피트니스 — iPhone

- **PWA로는 불가**. HealthKit은 네이티브 앱만 읽는다 [근거: 공식 문서 대신 업계 설명과 우회 앱 다수로 확인 — [예시](https://www.positioniseverything.net/apple-health-data-api-build-a-free-shortcut-export-pipeline/); Apple 공식 문서 직접 확인은 [확인 필요]]. 마이로그 iOS 네이티브 앱을 만들면 같은 Capawesome 플러그인으로 가능하지만 App Store 심사·개발자 계정 비용이 들어 **대표님 결정(PWA만)과 충돌**.
- **대안 1 — 단축어(Shortcuts)**: '건강 샘플 찾기'로 최근 체중·체지방을 읽어 글로 만들고 클립보드에 복사 → 마이로그 붙여넣기 칸. 서버 없이 가능 [추정: 단축어 동작은 업계 사례로 확인, 마이로그용 단축어는 만들어 시험해야 함]. 단축어 자동화로 매일 정해진 시각 실행도 가능 [근거: [Health Auto Export 설명](https://apps.apple.com/app/id1115567069)].
- **대안 2 — 전체 내보내기**: 건강 앱 '모든 건강 데이터 내보내기' → `export.xml`(체중은 `HKQuantityTypeIdentifierBodyMass`, 체지방은 `BodyFatPercentage`) [근거: [파서 예](https://github.com/freddiefujiwara/ahcd), [pypi](https://pypi.org/project/parse-apple-health-data/)]. 파일이 수백 MB가 될 수 있어 브라우저에서 **스트리밍으로 필요한 줄만** 읽어야 함 [추정].
- **대안 3 — 내보내기 전용 앱**(Health Auto Export 등)이 JSON·CSV를 만들어 줌. 유료 앱 의존이라 선택지로만 안내.

### InBody(인바디 앱·LookinBody)

- **LookinBody Web API는 유료 B2B**: 신청서 → 승인 → 키 발급, 서버 IP 등록·웹훅, 구독 필요 [근거: [API 키 설정](https://lbwebfaq.inbodyusa.com/support/solutions/articles/69000848771-lb-web-integration-api-key-setup), [이용약관](https://inbodyusa.com/static/assets/files/LB%20Web%20API%20-%20Terms%20of%20Use%20(v4).pdf)]. 헬스장·병원용. → **사실상 불가**.
- **인바디 앱 → 삼성 헬스 → Health Connect**: 인바디 앱이 삼성 헬스와 연동된다는 삼성 커뮤니티 답변이 있으나 모델별로 다름 [근거: [커뮤니티](https://r1.community.samsung.com/t5/samsung-health/%EC%82%BC%EC%84%B1%ED%97%AC%EC%8A%A4-%EC%B2%B4%EC%A4%91-%EA%B8%B0%EB%8A%A5%EC%97%90%EC%84%9C-%EC%95%B3%ED%94%8C%EB%A6%AC-%EC%8A%A4%EB%A7%88%ED%8A%B8-%EC%9D%B8%EB%B0%94%EB%94%94-%EC%B2%B4%EC%A4%91%EA%B3%84-t8-%EC%97%B0%EB%8F%99-%EA%B0%80%EB%8A%A5%ED%95%9C%EA%B0%80%EC%9A%94/m-p/19287909/highlight/true)]. 골격근량은 위 이유로 기대 어려움.
- **결론: 인바디는 사진 OCR을 계속 주력으로**, 체중만 Health Connect로 보조. 인바디 앱 결과 화면 **캡처를 공유하기로 바로 받는 것**(2부 2-4)이 사용자에게 가장 짧은 길.

### Garmin(가민)

- **개인 API(2026-10 공개)**: 가민 커넥트 웹에서 본인이 키를 만들고, 키로 24시간 토큰을 받아 **본인 데이터만** 읽음(JSON 요약·FIT). 승인 없음. 단 **여러 사용자를 위한 상업 앱 용도가 아님** [근거: [가민 개인 API](https://developer.garmin.com/gc-developer-program/personal/personal-api), [FAQ](https://developer.garmin.com/gc-developer-program/personal/personal-faq/), [기사](https://the5krunner.com/2026/10/22/garmin-personal-api/)]. 브라우저에서 바로 부를 수 있는지(CORS)는 [확인 필요]. 사용자 각자가 키를 넣는 '고급 설정'으로만 가능성 있음.
- **사업자 프로그램(Health API 등)**: 승인된 사업자에게 무료지만 심사가 길거나 일시 중단 보고 [근거: [가민 개요](https://developer.garmin.com/gc-developer-program/overview), [포럼](https://forums.garmin.com/developer/connect-iq/f/discussion/440200/connect-developer-program-activity-api-access-no-response-is-the-program-still-paused)]. → 신청해도 어려움.
- **실용 경로**: 가민 커넥트 앱 → Health Connect(가민이 어떤 유형을 쓰는지 [확인 필요]) 또는 **FIT 파일 가져오기**.

### Fitbit / Google

- 옛 Fitbit Web API는 2026년 9~11월 종료 예정, 후속 Google Health API는 **모든 권한이 '제한' 범위라 개인정보·보안 심사 필요** [근거: [Google Health API 소개](https://developers.google.com/health/about?hl=en), [마이그레이션](https://developers.google.com/health/migration)]. Google Fit API도 2026년 종료 [근거: [Fit 마이그레이션](https://developer.android.com/health-and-fitness/health-connect/migration/fit)]. → 웹 API는 사실상 불가, **Fitbit 앱 → Health Connect** 경로.

### Withings

- **공개 API, 계약 없이 OAuth** 앱 등록, 체중(type 1)·체지방률(6)·체지방량(8)·제지방량(5) [근거: [Withings 개발자](https://developer.withings.com/), [API 요약](https://developer.withings.com/llms.md)]. 무료 한도·요금표는 [확인 필요].
- OAuth 토큰 교환에 **비밀키를 둘 서버**가 필요 → 지금 구조로는 어려움. Withings는 삼성 헬스와도 연결된다 [근거: [Withings 지원](https://support.withings.com/hc/articles/46965471702801)] → Health Connect 경로가 현실적.

### Polar / Coros / Suunto / Strava

| | 공개 여부 | 마이로그에 맞나 |
|---|---|---|
| Polar AccessLink | 무료 개발자 등록, 읽기 전용 OAuth [근거: [Polar](https://www.polar.com/accesslink-api/)] | 서버 필요. 사용자 적음 [추정] → FIT·GPX 파일 |
| Coros | 파트너 API는 **사용자 기반 있는 등록 회사**만, 신청 메일·양식 [근거: [Coros 신청](https://support.coros.com/hc/en-us/articles/17085887816340-Submit-an-API-Application)] | 지금은 불가 → 파일 |

### 중복·충돌 규칙
1. 가져온 기록마다 `source`(예: `hc:com.sec.android.app.shealth`)와 **외부 ID**(Health Connect 레코드 ID)를 저장 → 다시 읽어도 같은 ID는 건너뜀.
2. 같은 종류가 **10분 안 + 값 차이 0.1 kg(또는 0.2%p) 이하**면 같은 측정으로 봄. 사람이 직접 넣은 값이 있으면 **사람 값 우선**, 가져온 값은 숨김(삭제 아님).
3. 하루에 체중이 여러 번이면 지금처럼 모두 저장하고, 그래프는 기존 규칙(예: 그날 첫 값)을 따른다 [코드: `body-series.js` 규칙 확인 필요].
4. **첫 가져오기는 미리보기 화면**("지난 30일 체중 12개, 운동 5개를 가져올까요?") → 이후엔 앱을 열 때 조용히 새 것만. 끄기·출처별 선택은 설정에서.
5. 가져온 기록을 사람이 고치면 그 기록은 '고친 기록'이 되어 다음 가져오기가 덮지 않음.
6. AI 검토함과는 별개 — 측정 기기 값은 추정이 아니라서 검토함을 거치지 않는 게 자연스럽다 [추정]. 단 첫 미리보기가 그 역할을 한다.

# 2부. 직접 입력 편의성 — 추가 제안

각 항목: 무엇 / 왜(근거) / 참고 / 작업 규모(작·중·대, [추정]) / 우선순위(빠름·중간·장기).

## 2-1. 한국식 끼니를 더 빨리

**(1) '한상' 틀** — 밥(공기)·국(그릇)·반찬 칸이 미리 있는 끼니. 반찬은 '조금·보통·많이'.
- 왜: 한국 식사는 밥+국+김치+반찬 2~3가지가 기본이고, 반찬은 나눠 먹어 개인 양을 g로 말하기 어렵다 [근거: [Nutr Res Pract 2021](https://synapse.koreamed.org/articles/1147489)].
- 참고: 눔 한국판의 '그릇' 단위 선택 [근거: [PMC5537862](https://pmc.ncbi.nlm.nih.gov/articles/PMC5537862)].
- 반찬 '보통' 기준량은 국가 식품 DB의 1회 분량을 참고해 정함 [확인 필요]. · 중 · **중간**

**(2) 편의점·프랜차이즈 '내 메뉴'** — 한 번 넣은 상품·메뉴는 이름 그대로 다음에 1번 누름. 상품 사진(포장)을 함께 저장해 목록에서 알아보기 쉽게.
- 왜: 포장식품·패스트푸드는 기록이 가장 쉬운 종류(7점 중 6.3~6.5)라, 한 번 등록하면 반복 비용이 거의 0 [근거: [Cordeiro 외 CHI 2015](https://pmc.ncbi.nlm.nih.gov/articles/PMC4755274)]. 다신은 브랜드·프랜차이즈 칼로리 사전을 핵심 기능으로 둔다 [근거: [다신 스토어](https://apps.apple.com/kr/app/id981460948)]. · 작 · **빠름**

**(3) 배달 주문 글 공유 → 바구니** — 배달앱 주문 상세에서 '공유'한 글(가게명·메뉴·수량)을 이미 있는 공유 받기로 받아, 메뉴 줄을 바구니에 넣음. 칼로리는 '내 메뉴'에 있으면 그대로, 없으면 '대충'으로.
- 왜: 성인 4명 중 1명은 하루 한 끼 이상 배달·포장 [근거: [보도](https://www.insight.co.kr/news/538597), 2차 자료]. 가계부 앱이 금융 문자 200여 종을 붙여넣기로 인식하는 것과 같은 방식 [근거: [편한가계부](https://apps.apple.com/kr/app/%ED%8E%B8%ED%95%9C%EA%B0%80%EA%B3%84%EB%B6%80-pc-%EA%B0%80%EA%B3%84%EB%B6%80/id564730202)].
- 배달앱마다 공유 글 형식이 다름 → 2~3개 앱 실물 수집 후 규칙 작성 [확인 필요]. AI 없이 규칙으로. · 중 · **중간**

**(4) 회식·술 단위** — 소주(잔·병, 1병=7잔 기본), 맥주(잔·500cc·캔), 막걸리(사발·병), 와인(잔). '안주 대충' 한 칸. 술은 칼로리만 세고 탄단지는 비움. · 작 · **중간**

**(5) 구내식당·급식 메뉴판** — 메뉴판 사진/글을 공유하면 줄 단위로 나눠 '한상' 칸에 채움(OCR은 이미 있음). · 중 · 장기

## 2-2. 한 손 입력

**(6) 엄지 닿는 곳에 입력** — 검색칸·저장 버튼·양 칩을 화면 **아래쪽**에 두고, 결과 목록은 위로 쌓임(키보드 바로 위 검색칸). 큰 숫자 키패드(양·체중)를 앱 안에 둬 기본 키보드 전환을 줄임.
- 왜: 사람들의 약 절반(49%)이 한 손으로 폰을 들고 엄지로 누른다 [근거: [Hoober, UXmatters 2013](https://uxmatters.com/mt/archives/2013/02/how-do-users-really-hold-mobile-devices.php)]. 엄지 영역 지도는 자세에 따라 달라 지나치게 믿지 말 것 [근거: 같은 연구의 후속 비판, [Smashing](https://smashingmagazine.com/2020/02/design-mobile-apps-one-hand-usage/)].
- 참고: 은행 앱 이체 금액 입력의 큰 숫자 키패드 [추정: 토스 공식 근거 못 찾음]. · 중 · **빠름**

**(7) 체중 한 손 입력** — 지난 값에서 시작하는 큰 숫자 + `−0.1 / +0.1` 길게 누르면 연속. 대부분 전날과 ±1 kg 안이라 [추정] 키보드 없이 2~5번 누름. · 작 · **빠름**

## 2-3. 앱을 열지 않고 / 덜 열고 기록

**(8) 앱 아이콘 길게 누르기 바로가기** — '체중 기록', '어제 그대로(지금 시간대 끼니)', '운동 이어서', 'AI로 입력'. 
- 참고: Capacitor 앱 바로가기 플러그인 [근거: [Capawesome App Shortcuts](https://capawesome.io/docs/sdks/capacitor/app-shortcuts/)]. · 작 · **빠름**

**(9) 홈 화면 위젯** — 작은 위젯: 오늘 칼로리·체중 한 줄 + `＋` 두 개(식사·체중). 큰 위젯: '어제 이 시간에 먹은 것' 1번 누름 기록.
- 왜: 수면 일지에서 위젯으로 입력 거리를 줄이자 준수율이 73%→92% [근거: [SleepTight](https://terpconnect.umd.edu/~choe/download/UBICOMP-2015-Choe-SleepTight.pdf)]. Google Keep '빠른 메모'·Todoist '할 일 추가' 위젯이 같은 패턴 [근거: [Keep](https://support.google.com/keep/answer/13302793), [Todoist](https://www.todoist.com/help/articles/use-a-todoist-widget-on-your-android-device-632pZA)].
- Capacitor에는 표준 위젯 플러그인이 없어 **안드로이드 네이티브 코드** 필요 [근거: [Ionic 포럼](https://forum.ionicframework.com/t/capacitorjs-2024-is-there-a-way-to-add-widgets-for-apps/242306)]. · 대 · **중간**

**(10) 공유하기 확장** — 지금은 글만 받는다 [코드]. 여기에 **사진**(인바디 결과지·앱 캡처·음식·메뉴판)과 **파일**(FIT·GPX·CSV·XML)을 받게 해서, 받은 종류에 따라 바로 해당 화면으로: 인바디 사진 → OCR 확인, FIT → 운동 가져오기, 배달 글 → 바구니.
- 참고: 메신저 '나에게 보내기'처럼 어디서든 공유로 기록. PWA는 `share_target`을 POST·파일로 바꿔야 함 [근거: [Web Share Target](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target)]. · 중 · **빠름**

## 2-4. 말로 기록하기

**(11) 키보드 마이크부터** — 갤럭시·Gboard 키보드의 마이크는 **어떤 입력칸에서나 이미 된다**. 그래서 먼저 할 일은 기능 추가가 아니라 **검색칸이 문장을 알아듣게** 하는 것: "점심 제육 1인분 밥 반 공기" → 제육(1인분)·쌀밥(반 공기)·점심 시각. 규칙 기반(음식 이름 사전 + 숫자·단위·끼니 말), AI 불필요.
- 왜: Android WebView에는 웹 음성 인식 API가 **아예 없다** → 앱 안 음성 버튼은 네이티브 플러그인이 필요 [근거: [Chromium 이슈](https://issues.chromium.org/41172064), [Capgo 음성 인식](https://capgo.app/docs/plugins/speech-recognition/getting-started/)]. 키보드 마이크는 추가 작업이 없다.
- 참고: Todoist의 말하듯 적기·Ramble [근거: [Todoist 날짜](https://www.todoist.com/help/articles/introduction-to-dates-and-time-q7VobO), [위젯](https://www.todoist.com/help/articles/use-a-todoist-widget-on-your-android-device-632pZA)], MyFitnessPal 음성 기록도 '말 → 후보 → 사람 확인' [근거: [기사](https://androidguys.com/news/myfitnesspal-introduces-voice-log-feature-for-faster-easier-food-tracking/)]. · 중 · **중간** (앱 안 마이크 버튼은 장기)

## 2-5. 바코드

**(12) '한 번 등록하면 다음부터 바로'** — 바코드를 찍으면 ① '내 음식'에 그 바코드가 있으면 즉시 바구니 ② 없으면 **영양성분표 사진 OCR**(이미 있는 한국어 OCR)로 값을 채워 등록하고 바코드를 붙여 둠.
- 스캔: ML Kit 플러그인, **오프라인·Play 서비스 불필요**, EAN-13 지원, 앱 크기 몇 MB 증가 [근거: [Capawesome ML Kit](https://capawesome.io/docs/sdks/capacitor/mlkit/barcode-scanning/), [ML Kit](https://developers.google.com/ml-kit/vision/barcode-scanning)]. 일부 기기 동작 차이 보고 → 노트8 시험.
- 국내 DB 현실:
  - 식약처 **식품영양성분 DB(가공식품)** 는 공공데이터포털 API로 제공, 인증키·일일 호출량 제한 있음 [근거: [식약처 소개](https://www.mfds.go.kr/brd/m_580/view.do?seq=69), [공공데이터 표준](https://www.data.go.kr/data/15100066/standard.do)]. **바코드로 바로 찾는 칸이 있는지는 [확인 필요]**.
  - 식약처 '바코드연계제품정보' API는 바코드·품목보고번호·제품명을 주지만 **영양값은 없고**, 외부 연계라 별도 승인이 필요할 수 있음 [근거: [wikidocs 목록](https://wikidocs.net/479417); 명세는 [확인 필요]]. 즉 '바코드 → 제품명 → 영양 DB 검색' 두 단계가 될 가능성.
  - Open Food Facts는 키 없이 무료지만 **ODbL(공유 조건)** 이고 한국 상품은 빈 곳이 많을 것 [근거: [라이선스](https://wiki.openfoodfacts.org/ODBL_License), [한국 페이지](https://kr.openfoodfacts.org/data)].
  - 공공 API 호출은 키를 앱에 넣어야 해 노출 위험 [추정] → 1차는 **DB 없이 '내 바코드' 방식**으로 시작, 공공 DB는 관리자가 자주 쓰는 상품만 미리 넣는 방식 검토.
- · 중 · **중간**

## 2-6. 사진은 보조로

**(13) '찍어만 두기'** — 바쁠 때 사진만 찍어 그 시각에 '정리 안 된 끼니'로 저장 → 저녁에 '정리할 값' 카드(이미 있음)에 모여 한 번에 정리. 사진에서 칼로리를 자동 확정하지 않음.
- 왜: 사진 기록을 쓴 사람이 오히려 덜 꾸준했고 [근거: [Yale 2022](https://news.yale.edu/2022/09/15/when-counting-calories-words-are-more-valuable-pictures)], 사진 AI 칼로리는 과소 추정 경향(예비 결과) [근거: [초록 정리](https://www.epocrates.com/online/article/ai-calorie-counting-apps-miss-a-third-of-meal-calories)]. 사진은 '기억 보조'로 쓰는 게 근거에 맞다. · 작 · **빠름**

## 2-7. 운동 중 한 손 기록

**(14) 세트 한 줄 = 큰 ✓ 하나** — 지난 값이 미리 채워진 세트 줄 오른쪽에 큰 ✓. 무게·횟수는 ✓ 전에 `−/+`로만. 다음 세트로 자동 스크롤.
- 참고: Hevy의 PREVIOUS 열과 한 번 누름 완료 [근거: [Hevy 도움말](https://help.hevyapp.com/hc/en-us/articles/36011896355479)], 번핏의 세트 복사·이전 기록 불러오기 [근거: [번핏](https://apps.apple.com/KR/app/id1503464984)]. · 중 · **빠름**

**(15) 휴식 타이머 + 잠금화면 알림** — ✓를 누르면 휴식 타이머 시작, 끝나면 진동 한 번. 진행 중 운동은 **알림 줄에 '다음 세트: 레그프레스 60kg × 10 [완료]'** 를 띄워 잠금 화면에서 바로 완료. 로컬 알림 플러그인은 이미 있음 [코드]. 알림 버튼 동작은 [확인 필요].
- 참고: Hevy 자동 휴식 타이머 ±15초 [근거: [Hevy 휴식](https://www.hevyapp.com/features/workout-rest-timer/)], Strong 자동 카운트다운 [근거: [Strong](https://apps.apple.com/app/id464254577)]. · 중 · **중간**

**(16) 운동 중 화면 꺼짐 방지**(선택) — 운동 화면에서만. · 작 · 빠름

**(17) 루틴 = '지난 ○○ 그대로'** — 요일별 루틴을 따로 만들게 하기보다, '지난 하체 그대로' 한 번 누름으로 종목·세트를 복사(값은 지난 값). 대부분 사람은 루틴을 명시적으로 만들지 않는다 [추정]. · 작 · **빠름**

## 2-8. 실수 복구

**(18) 휴지통 7일** — 지운 끼니·운동·수치는 7일간 '최근 지운 기록'에 남음. 확인창 대신 되돌릴 수 있어 마음이 편함.
- 근거: 확인창은 되돌릴 수 없는 일에만 [근거: [NN/g](https://www.nngroup.com/articles/confirmation-dialog/)], Google Drive는 삭제 대신 휴지통+되돌리기 [근거: [LogRocket](https://blog.logrocket.com/ux-design/double-check-user-actions-confirmation-dialog)]. Firebase 동기화와 충돌하지 않게 '삭제 표시' 방식 필요 [추정]. · 중 · **중간**

**(19) 실수 탐지 몇 가지**(규칙)
- 1분 안에 같은 끼니가 두 번 저장 → "두 번 눌렸나요? 하나로 합칠까요?"
- 체중이 전날보다 3 kg 넘게 차이 → "73.2 맞나요? (어제 70.1)" — 소수점 위치 실수(732·7.32) 잡기.
- 다른 날을 보고 있다가 기록하면 저장 버튼에 날짜를 크게("11/20(목)에 저장"). · 작 · **빠름**

**(20) 기록 변경 내역** — 기록을 열면 아래 작게 "처음 12:31 직접 입력 · 12:40 양 바꿈 · AI 정리". 사람과 AI 중 누가 바꿨는지 보이면 AI를 믿기 쉬워짐 [추정]. · 중 · 장기

## 2-9. 기록 리듬 — 압박 없이

대표님 결정(식단·운동은 알리지 않음)을 그대로 두고, **알림이 아닌 방법**으로 리듬을 만든다.

**(21) 보이는 곳에 두기** — 위젯·바로가기(8·9)가 알림 역할을 대신한다. 사용자가 폰을 켤 때 이미 '오늘 2끼 · 1,240 kcal'가 보이면 따로 부를 필요가 없다 [추정].

**(22) 운동 중 알림만 '진행형'으로** — 사용자가 시작한 운동이 진행 중일 때만 알림 줄 표시(15). 사용자가 시작한 일의 연장이라 압박이 아님 [추정].

**(23) 하루 끝 '오늘 정리' 선택 기능(기본 꺼짐)** — 켠 사람만, 정해진 시각에 "오늘 정리할 끼니 1개 · 사진만 찍어 둔 것 1개". 기록이 0개인 날은 **보내지 않음**(빈 날 지적 금지).
- 왜: 알림은 단기 참여를 올리지만 반복되면 피로·습관화로 효과가 줄고, 적응형 시점이 늘 나은 것도 아니다 [근거: [Drink Less MRT](https://pmc.ncbi.nlm.nih.gov/articles/PMC10337295), [Healthy Mind 시험](https://pmc.ncbi.nlm.nih.gov/articles/PMC5207732), [강화학습 알림](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC8200090/)]. → 기본 꺼짐, 사용자가 시각을 정하고, 할 일이 있을 때만. · 작 · 중간

## 3. 전체 우선순위

### 빠름 (1~2주, 데이터 형식 거의 그대로)
1. **Health Connect 시험판**(체중·체지방) + 실기기 확인 — 1부 1순위
2. 공유하기 확장(사진·파일) → 인바디 캡처·FIT 바로 받기 (10)
3. 앱 바로가기 (8), 체중 한 손 입력 (7), 엄지 쪽 입력 배치 (6)
4. 운동: 큰 ✓·지난 값 (14), '지난 ○○ 그대로' (17), 화면 꺼짐 방지 (16)
5. 실수 탐지 규칙 (19), '찍어만 두기' (13), 편의점·프랜차이즈 '내 메뉴' (2)

### 중간 (1~2달)
6. Health Connect 운동·걸음, 중복 규칙, 연결된 앱 설정, 처리방침·민감정보 동의
7. iPhone 단축어, 파일 가져오기(FIT·GPX·삼성 CSV·Apple XML)
8. 한상 틀 (1), 회식·술 (4), 배달 글 해석 (3), 문장 해석 검색칸 (11)
9. 바코드 '내 바코드' (12), 휴지통 (18), 휴식 타이머·잠금화면 알림 (15)
10. 홈 위젯 (9), '오늘 정리' 선택 알림 (23)

### 장기
11. 앱 안 음성 버튼, 구내식당 메뉴판 (5), 변경 내역 (20)
12. 서버가 생기면 Withings·Polar, 회사 요건을 갖추면 삼성 Data SDK·가민 사업자 API
13. Play 스토어 게시(건강 앱 신고·데이터 보안)

## 4. 측정

- 연동: 연결한 사용자 비율, 가져온 체중 중 사람이 고친 비율(오류 대리 지표), 직접 입력 체중 횟수 변화(연동이 입력을 대신했는지).
- 편의성: 앞 제안서의 '누름 수 표'에 시나리오 추가 — 바로가기로 체중 기록, 배달 주문 공유로 끼니 기록, 바코드 재구매 상품 기록, 운동 세트 1개 완료.

## 5. 대표님 결정이 필요한 것

1. Health Connect에서 **걸음·활동 칼로리를 '보기만'** 할지, 기록·통계에도 넣을지.
2. 가져온 체중을 **첫 미리보기 뒤 자동 저장**할지, 매번 확인할지.
3. 마이로그 식단을 Health Connect(→삼성 헬스)에 **쓰기**까지 할지.
4. 개인정보 처리방침을 어디에 게시할지(공개 웹 주소 필요).
5. 바코드용 공공 DB 인증키를 앱에 넣는 위험을 받아들일지, '내 바코드' 방식만으로 시작할지.
