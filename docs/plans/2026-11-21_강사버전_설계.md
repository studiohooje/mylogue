## 1. 한 줄 요약
승인된 강사는 헤더 토글로 '강사 모드'에 들어간다. 관리 중인 회원(연동 또는 미가입)을 골라, 회원별 템플릿을 불러와 수업을 입력하고 보낸다. 회원에게는 검토함 + 알림(앱 안·푸시)으로 도착하고, **회원이 확정해야** 회원 기록이 된다. PT 회차는 보낼 때 자동 차감되고(끌 수 있음), 그룹 수업은 한 번에 여러 회원에게 보낸다. 강사는 대시보드에서 회원 현황(보낸 수업 + 동의한 범위)을 보고, '일정'에서 수업을 예약한다.

## 2. 역할과 상태

| 역할 | 조건 | 할 수 있는 일 |
|---|---|---|
| 일반 사용자(회원) | 이용 승인 | 자기 기록, 강사 연동 수락·끊기, 공유 범위 선택 |
| 강사 | 관리자가 `roles.trainer=true` | 강사 모드, 회원 관리, 수업 보내기, 템플릿, 대시보드, 일정 |
| 관리자 | 기존 | 강사 자격 승인·해제 |

- 강사도 평소에는 일반 사용자다. 토글을 '내 기록'에 두면 지금 앱 그대로다.
- 강사 자격이 해제되면 강사 모드가 사라진다. 회원 쪽 기록(이미 확정된 것)은 그대로 남는다.

### 연동 상태 머신
`invited`(강사가 코드·링크·QR 생성, 7일 유효) → `active`(회원 수락) → `ended`(어느 한쪽이 끊음)
- 미가입 회원: 강사 쪽에만 있는 `offline` 회원. 초대 수락 시 `active`로 바뀌고, 쌓인 수업을 '한꺼번에 받기'로 보낸다(§6.4).

## 3. 데이터 모델(Firestore, Spark 유지)

| 경로 | 필드 | 쓰는 사람 |
|---|---|---|
| `users/{uid}` | `roles.trainer:boolean`(관리자만), `trainerProfile{displayName, gym, kind:'pt'|'pilates'|'both', bio}`, `plan:{tier:'free'|'premium', seats:10}` | 관리자 / 본인(프로필) / (나중) 결제 서버 |
| `trainerApplications/{uid}` | `displayName, gym, kind, note, status:'pending'|'approved'|'rejected', createdAt` | 본인 생성 / 관리자 심사 |
| `invites/{code}` | `trainerUid, clientId(offline 회원과 연결 시), expiresAt, usedBy, createdAt` | 강사 생성 / 회원 사용(1회) |
| `links/{trainerUid}_{memberUid}` | `status, scope{sessions:true(고정), workouts:false, diet:false, body:false}, consentAt, warnedTrainerAt, warnedMemberAt, endedAt, endedBy` | 강사(생성) · 회원(수락·범위·끊기) · 강사(끊기) |
| `users/{trainerUid}/clients/{clientId}` | `memberUid|null(offline), name, goal, cautions, pt{total, used, expiresAt}, groups[], lastSessionAt` | 강사 본인 |
| `users/{trainerUid}/clients/{clientId}/templates/{id}` | `title, exercises[], notes, lastUsedAt` | 강사 본인 |
| `users/{trainerUid}/sessions/{id}` | 수업 원본(운동·메모·그룹 여부·대상 회원들·회차 차감 여부)과 회원별 전송 상태 `{memberUid:{draftId, status:'sent'|'confirmed'|'edited'|'rejected'|'queued'}}` | 강사 본인 |
| `users/{memberUid}/aiDrafts/{id}` | **기존 검토함 재사용**: `type:'workout'`, `sourceModel:'trainer'`, `evidence{trainerUid, trainerName, sessionId, ptDeduct:boolean}` | 강사 생성(active·scope) / 회원 처리 |
| `users/{memberUid}/records/...workouts` | 확정 시 `trainerSession{trainerUid, sessionId, ptDeduct}` 기록 | 회원 |
| `sessionAcks/{trainerUid}_{sessionId}_{memberUid}` | 회원 처리 결과 회신(`confirmed|edited|rejected`, `edits` 요약, `feedback{effort, pain[], note}`) | 회원 생성 / 강사 읽기 |
| `schedules/{id}` | 수업 예약 `trainerUid, memberUids[], startAt, durationMin, place, status:'planned'|'done'|'canceled', sessionId` | 강사 / 회원 읽기·응답 |
| `users/{uid}/devices/{id}` | 푸시 토큰(FCM), 플랫폼, 알림 설정 | 본인 |

- **검토함 재사용**의 이점: 확정·수정·버리기, 중복 방지(내용 지문), 일괄 처리, 알림이 이미 있다. 출처 배지만 'AI'와 '강사 ○○'로 나눈다.
- **강사가 보낸 수업 열람**: 강사는 자기 `sessions`(원본)와 `sessionAcks`(회원 처리 결과)로 본다. 회원 기록 전체를 읽지 않는다.
- **동의 범위 열람**(scope.workouts/diet/body가 참일 때만): 회원 기록 문서 읽기를 규칙으로 허용한다. 기본은 거짓이다.

### 보안 규칙 요지(에뮬레이터 시험 필수)
- `roles`·`plan`은 관리자(나중엔 결제 서버)만 쓴다.
- 강사의 `users/{m}/aiDrafts` 생성 조건: `links/{auth.uid}_{m}.status=='active'`이고, 문서는 `sourceModel=='trainer'`, `evidence.trainerUid==auth.uid`, `status=='pending'`, `type=='workout'`이어야 한다. 처리(확정·수정·버리기)는 회원만 한다.
- 회원 기록 읽기(강사): 해당 scope 필드가 참이고 link가 active일 때만 허용한다.
- `sessionAcks`: 회원만 생성하고, 해당 강사만 읽는다.
- 연동 끊기는 양쪽 모두 가능하다. `ended` 이후에는 위의 모든 허용이 즉시 사라진다(규칙이 link 상태를 매번 확인).
- 무료 한도(§10): 강사의 active+offline 회원 수가 `plan.seats`를 넘으면 새 연동 생성을 막는다(규칙 + 앱 둘 다).

## 4. 화면 — 강사

### 4.1 헤더 토글
- 승인된 강사만 `내 기록 | 강사` 토글이 보인다.
- 강사 모드일 때는 헤더 테두리를 보라색으로 바꾸고 '강사 모드' 배지를 붙여서, 내 기록과 헷갈리지 않게 한다.

### 4.2 강사 모드 하단 메뉴
`회원 · 대시보드 | 일정 · ＋수업 입력 | 템플릿 · 설정`(가운데 특별 버튼 2개 구조 유지)

### 4.3 회원
- 목록: 이름, 상태 배지(연동·대기·미가입·끊김), 마지막 수업일, 이번 주 횟수, **PT 남은 회차/만료일**, 그룹 태그
- 회원 추가 두 가지
  - '앱 회원 초대': 코드(8자리) / 링크 / QR 생성, 7일 유효
  - '미가입 회원으로 기록 시작': 이름만 입력. 나중에 초대
- 회원 상세
  - 목표·주의사항(부상), PT 회차(총·사용·만료)
  - 보낸 수업 이력(상태: 확정·고침·거절·대기)
  - 회원 피드백(강도·불편 부위)
  - 동의한 범위의 기록(운동·식단·수치), 각 항목 옆에 '회원 동의' 표시

### 4.4 수업 입력(가장 많이 쓰는 화면)
1. 대상: 회원 1명 또는 **그룹**(여러 회원 체크, 그룹 저장 가능)
2. 불러오기: 이 회원의 지난 수업 / 저장한 템플릿 / 공용 템플릿
3. 입력: 지금의 빠른 운동 입력을 그대로 쓴다(대분류 → 종목 → 머신 → 세트, 근육 자동 지정, 시간 종목).
   - 필라테스는 수업 시간·형태·강도·메모를 쓴다. 기구·동작 상세는 필라테스 자문 결과를 반영한다.
4. 강사 메모: 회원에게 보이는 코멘트, 그리고 강사만 보는 메모
5. **PT 회차 차감**: 기본 체크. 그룹 수업이면 회원마다 체크한다.
6. **보내기 확인**
   - "○○님에게 오늘 수업(하체 · 5종목 18세트)을 보낼까요? · PT 1회 차감(남은 7회 → 6회)"
   - 차감을 끄면 **경고**: "⚠ 회차 차감이 꺼져 있어요. 이 수업은 PT 횟수에서 빠지지 않아요."
7. 보낸 뒤: 템플릿으로 저장 제안. 일정에 '완료' 반영(예약과 연결된 경우).

### 4.5 대시보드
- **오늘**: 예약된 수업, 확정 대기, 회원이 고친 수업, 회차가 곧 끝나는 회원(3회 이하·만료 14일 이내)
- **회원별 카드**
  - 최근 4주 수업 횟수, 출석률(예약 대비)
  - 부위 균형(보낸 수업 기준), 주요 종목 무게 진행(보낸 수업 기준)
  - 회원 피드백 추이(강도 평균, 반복되는 불편 부위)
  - 회원이 동의한 경우: 수업 밖 운동 횟수, 체중 추세, 식단 기록률
- **매출 참고**(선택): 이번 달 차감된 PT 회차 수
- 나중에: AI 코치(프리미엄)와 연결해서 '다음 수업 추천'을 받는다.

### 4.6 템플릿
- 회원별 템플릿, 공용 템플릿(강사의 루틴 라이브러리), 그룹 수업용 템플릿
- 마지막 사용일 순으로 보여 준다. 복제·수정·삭제할 수 있다.

## 5. 화면 — 회원

### 5.1 연동 수락
- 코드 입력 / 링크 열기 / QR 스캔 → 강사 정보 확인 → **공유 범위 선택** → 수락
- **경고(필수, 회원에게)**: "강사님께 기록 공유를 강요받지 않아도 돼요. 수업 기록 외의 운동·식단·수치는 원할 때만 켜고, 언제든 끌 수 있어요."
- 공유 범위 토글: 강사님이 보낸 수업(항상) / 내가 따로 한 운동 / 식단 / 수치. 기본은 모두 꺼짐.

### 5.2 수업 받기
- 앱 안 알림(중요 알림처럼 자동으로 뜸)과 푸시: "○○ 강사님이 오늘 수업(하체 · 5종목 18세트)을 보냈어요"
- 검토함 카드: 출처 배지 '강사 ○○', 강사 코멘트, PT 차감 표시
  - 차감 꺼짐: **경고** "⚠ 이 수업은 PT 회차가 차감되지 않는 수업이에요. 알고 계신 내용이 맞나요?"
- 처리: 그대로 확정 / 고친 뒤 확정(강사에게 '고침' 알림 + 바뀐 항목 요약) / 버리기(강사에게 '거절')
- 확정할 때 한 줄 피드백(선택): 오늘 강도 1~10, 불편했던 부위, 메모

### 5.3 내 강사(설정)
- 연동된 강사 목록(여러 명 허용), 각 강사의 공유 범위 바꾸기, 연동 끊기
- PT 회차 보기(강사가 관리하는 값, 읽기 전용)

## 6. 주요 흐름 상세

### 6.1 연동 순간의 경고(양쪽)
- 강사 화면(초대 수락 알림을 받을 때): "회원에게 수업 외 기록 공유를 **절대 강요해선 안 됩니다.** 회원은 언제든 공유를 끄거나 연동을 끊을 수 있어요."
- 회원 화면: §5.1 문구.
- 둘 다 '확인'을 눌러야 연동이 끝난다. `warnedTrainerAt` / `warnedMemberAt`에 기록한다.

### 6.2 수업 보내기
`sessions` 원본 저장 → 대상 회원마다 `aiDrafts` 생성(트랜잭션, 내용 지문으로 중복 방지) → 푸시 요청 → 상태 `sent`

### 6.3 회원 처리 회신
회원이 확정·고침·버리기 → `sessionAcks` 생성 → 강사 대시보드·알림 갱신. 확정했고 차감이 켜져 있으면 강사 쪽 `pt.used+1`(강사 앱이 ack를 읽어서 반영. 회원은 강사 문서에 쓰지 않는다).

### 6.4 미가입(offline) 회원
- 강사 쪽에만 수업을 쌓는다(`queued`).
- 초대 수락 시 회원에게 "○○ 강사님이 미리 기록해 둔 수업 n개가 있어요. 받을까요?"를 띄운다. 받으면 n개 초안이 생기고 일괄 확정할 수 있다. 공유 범위 동의는 이때 함께 한다.

### 6.5 그룹 수업
- 한 번 입력하고 출석 체크한 회원들에게 각각 초안을 만든다. PT 차감은 회원별로 정한다.
- 회원별로 무게만 다르게 고칠 수 있는 '개인 조정' 칸을 둔다(같은 동작, 다른 무게).

## 7. '기록' 메뉴 → '일정'으로 발전
- 지금 '기록'(캘린더)은 날짜별 기록을 보는 곳이다. 여기에 **예약·스케줄**을 더해 '일정'으로 키운다.
- 회원(일반 사용자)
  - 달력에서 기록(먹은 것·한 운동·수치)과 **예정**(3.18.0 예정 기록, 강사 수업 예약)을 함께 본다.
  - 수업 예약 알림: 하루 전, 1시간 전(푸시 설정에 따름). 예약 확인과 변경 요청.
- 강사
  - 주간 타임테이블(시간 × 요일), 수업을 끌어서 옮기기, 반복 예약(매주 화·목 19:00)
  - 수업이 끝나면 '수업 입력'으로 바로 이어진다(예약에서 회원·시간이 자동으로 채워짐).
- 메뉴 이름: '기록' → **'일정'**(대표님 확인 필요, §14-1).

## 8. 푸시 알림
- **방식**: FCM(Firebase Cloud Messaging). 보내기는 Cloudflare 무료 서버(ai-worker와 같은 서버에 `/notify` 추가)가 FCM HTTP v1으로 한다. 서비스 계정 키는 서버 비밀값에만 둔다.
- **Android**: Capacitor 푸시 플러그인, 알림 권한 요청(Android 13+). **iPhone PWA**: iOS 16.4+ 홈 화면 추가 앱만 웹 푸시가 되고, 제약이 커서 앱 안 알림을 주로 쓴다.
- **설정 화면**(사용자별 켜기/끄기)
  - 강사 수업 도착 / 예약 알림(하루 전·1시간 전) / 예정 기록 확정 알림 / AI 검토함 / 강사용: 회원 확정·고침·거절
  - 조용한 시간(예: 23:00~07:00 보내지 않기)
- 푸시가 실패하거나 꺼져 있어도 앱 안 알림은 항상 뜬다.

## 9. 개인정보
- **최소 공유**: 기본은 강사가 보낸 수업뿐이고, 나머지는 회원이 항목별로 켠다.
- **철회**: 공유 끄기나 연동 끊기는 즉시 반영된다(규칙이 매 요청마다 확인).
- **강사 쪽 데이터**: 강사가 만든 수업 원본·템플릿·메모는 강사 소유다. 회원이 연동을 끊어도 강사의 '보낸 수업' 기록은 남지만, 회원의 다른 기록은 볼 수 없다.
- **회원 탈퇴**: 강사 쪽 `clients`에서 회원 식별 정보(memberUid)를 지우고 이름만 남길지는 §14-3에서 정한다. 회원 쪽 확정 기록은 회원과 함께 삭제한다.
- **감사 기록**: 공유 범위 변경과 연동·해제 시각을 남긴다(분쟁 대비).
- 동의 문구와 처리방침은 출시 전 법률 검토를 권한다(건강정보는 민감정보에 해당할 수 있음).

## 10. 과금 준비(지금은 무료)
- `users/{uid}.plan = {tier:'free', seats:10}`. 연동 회원과 미가입 회원을 합쳐 10명까지 무료다.
- 11번째 회원을 추가하면 '프리미엄이 필요해요' 안내를 띄운다. **지금은 한도를 아주 크게 설정해서 막지 않는다**(코드와 규칙은 준비해 두고 값만 바꾸면 켜지게).
- 결제를 붙일 때: 결제 서버(Cloudflare)가 `plan`을 갱신한다(사용자 수정 금지). AI 코치 프리미엄과 묶을지는 나중에 정한다.

## 11. 단계 계획(패치 단위)
1. **기반**: 강사 신청·승인, 역할, 헤더 토글, 강사 모드 껍데기, 규칙 + 에뮬레이터 시험
2. **연동**: 코드·링크·QR 초대, 수락, 양쪽 경고, 공유 범위, 끊기, 여러 강사
3. **수업 보내기**: 회원 목록(연동·미가입), 수업 입력(재사용), 검토함 출처 배지, 회신(확정·고침·거절)
4. **PT 회차·템플릿·그룹**: 차감 기본 체크·끄기 경고(양쪽), 회원별·공용 템플릿, 그룹 전송·개인 조정, 미가입 회원 일괄 전송
5. **대시보드**
6. **일정**: '기록' → '일정', 예약·반복·알림, 예약 → 수업 입력 연결
7. **푸시**: FCM, 설정 화면, 조용한 시간
8. **과금 스위치**: seats 한도 켜기, 결제 서버 연결

## 12. 시험(구현 시)
- 에뮬레이터 규칙 시험
  - 비강사는 강사 기능 불가
  - active가 아닌 강사의 전송 거부
  - scope가 꺼진 기록 열람 거부, 끊은 즉시 거부
  - 회원만 확정 가능
  - seats 한도
- 단위 시험: 세션 → 초안 변환(내용 지문·중복), PT 차감 계산, 그룹 전송, 미가입 일괄 전송, 경고 문구 표시 조건
- 화면 시험: 360·390·412·768·1280에서 강사 모드·회원 화면, 경고 다이얼로그

## 13. 더 발전시키면 좋은 점(제안)
- **출석 체크인**: 수업 시작할 때 회원 휴대폰으로 QR을 찍으면 출석과 '수업 입력 시작'이 한 번에 된다(PT 분쟁 방지에 강력함).
- **회원 목표 공유 카드**: 강사와 회원이 함께 보는 목표(예: 3개월 −5kg, 스쿼트 100kg)와 진행률
- **수업 사진·영상 메모**: 동작 교정 포인트를 짧게 첨부(용량이 커서 Storage·Blaze 비용 검토 필요)
- **노쇼·취소 규칙**: 예약 24시간 전 취소 시 회차 차감 여부 같은 센터 규칙 설정
- **센터 계정**(B2B): 여러 강사, 센터 관리자 승인, 센터 단위 통계·과금
- **강사 공개 프로필·후기**: 나중에 회원 유입 채널로 활용
- **AI 코치 × 강사**: 강사에게 '이 회원은 지난 2주 가슴 세트가 적어요' 같은 제안(프리미엄)

## 14. 남은 확인 사항
1. 하단 메뉴 '기록'을 **'일정'**으로 이름을 바꿀지(기록 보기 + 예약)
2. 강사 모드 하단 메뉴 구성(§4.2) 이대로 좋은지
3. 회원 탈퇴 시 강사 쪽에 남는 정보: 이름만 남김 / 전부 익명화
4. 예약 취소·노쇼 시 PT 회차 처리(센터마다 달라 강사가 회원별로 정하게 할지)
5. 수업 사진·영상 첨부를 1차에 넣을지(비용 때문에 나중 권장)
