# 강사(트레이너·필라테스 강사) 버전 설계 — 준비 문서

> 2026-11-21 대표님 요청. **아직 구현하지 않는다.** 나중 패치에서 바로 만들 수 있도록 구조·데이터·규칙·화면·시험을 미리 정해 둔다.
> 확정되지 않은 결정은 '§9 대표님 확인 필요'에 있다. 답을 받으면 이 문서를 고치고 구현한다.

## 1. 한 줄 요약

자격이 있는 강사가 헤더 토글로 '강사 모드'에 들어간다. 관리 중인 회원을 골라 오늘 한 운동을 입력(지난 템플릿 불러와 수정 가능)해서 회원에게 보낸다. 회원에게는 AI 검토함처럼 알림이 오고, **회원이 확정해야** 그 운동이 회원의 기록이 된다.

## 2. 사용자 흐름

### 강사
1. 강사 자격 신청 → 관리자 승인(§9-1) → 헤더에 '내 기록 | 강사' 토글이 생긴다(자격이 없으면 토글 자체가 없음).
2. 회원 연동: 강사가 초대 코드·링크를 만들고 회원이 수락한다(§9-2). 회원은 언제든 연동을 끊을 수 있다.
3. 강사 모드에서 '추가' → **회원 선택**(최근 수업 순, 검색) → 그 회원의 **템플릿 목록**(지난 수업, 저장한 루틴) → 불러와서 수정 → **보내기**.
4. 보낸 수업은 '대기 · 확정됨 · 회원이 고침 · 거절' 상태로 강사 화면에 보인다.
5. 강사 모드에서는 강사 본인의 기록(홈·헤일로·분석)은 건드리지 않는다. 토글을 '내 기록'으로 돌리면 평소 앱 그대로다.

### 회원
1. 강사 초대를 수락한다(무엇을 공유하는지 동의 화면, §9-3).
2. 수업이 끝나면 알림(종 + 중요 알림 자동 팝업, 3.18.0 예정 알림과 같은 방식)이 온다: "○○ 강사님이 오늘 수업(하체 · 5종목 18세트)을 보냈어요".
3. 검토함에서 그대로 **확정** / 고친 뒤 확정 / 버리기. 확정하면 내 운동 기록이 되고 헤일로·분석에 반영된다.
4. 설정 → '내 강사'에서 연동 목록 보기·끊기.

## 3. 데이터 (Firestore, Spark 그대로)

| 경로 | 내용 | 쓰는 사람 |
|---|---|---|
| `users/{uid}` | `roles.trainer: true`(관리자만 씀), `trainerProfile{name, gym, kind:'pt'|'pilates'|'both'}` | 관리자 / 본인(프로필만) |
| `links/{trainerUid}_{memberUid}` | `trainerUid, memberUid, status:'invited'|'active'|'ended', scope{sendWorkouts:true, viewWorkouts:bool, viewDiet:bool, viewBody:bool}, createdAt, endedAt, endedBy` | 강사(초대 만들기) · 회원(수락·끊기) |
| `invites/{code}` | 8자리 코드 → `trainerUid, expiresAt(7일), usedBy` | 강사 생성 · 회원 사용 |
| `users/{trainerUid}/clients/{memberUid}` | 강사 쪽 회원 메모: 표시 이름, 목표, 주의사항(부상), PT 남은 회차(§9-6) | 강사 본인만 |
| `users/{trainerUid}/clients/{memberUid}/templates/{id}` | 루틴 템플릿(운동 목록·세트·무게·메모), `lastUsedAt` | 강사 본인만 |
| `users/{trainerUid}/sessions/{id}` | 보낸 수업 사본 + 상태(회원 쪽 초안 id) | 강사 본인만 |
| `users/{memberUid}/aiDrafts/{id}` | **기존 검토함 재사용**: `type:'workout'`, `sourceModel:'trainer'`, `evidence{trainerUid, trainerName, sessionId}` | 강사(연동 active일 때만 생성) · 회원(확정·버리기) |

- 검토함을 재사용하면 확정·수정·버리기·중복 방지(내용 지문)·일괄 처리가 그대로 동작한다. 화면에서 출처 배지만 'AI'와 '강사'로 구분한다.
- 회원이 확정할 때 기록에 `trainerSession:{trainerUid, sessionId}`를 남겨 두면 나중에 '강사와 한 운동' 통계를 낼 수 있다.

### 보안 규칙 요지(구현 시 에뮬레이터 시험 필수)
- `roles.trainer`는 관리자만 쓴다(사용자 본인 수정 금지 — 지금 status 규칙과 같은 방식).
- 강사가 `users/{member}/aiDrafts` 생성: `exists(links/{auth.uid}_{member})`이면서 `status=='active'`이고 `scope.sendWorkouts`일 때만 허용한다. 문서는 `type=='workout'`, `status=='pending'`, `evidence.trainerUid==auth.uid`여야 한다. 확정·수정·삭제는 회원만 한다.
- 강사가 회원 기록 읽기는 §9-3 결정에 따라 `scope.view*`가 참일 때만 허용한다. 기본은 **불가**다.
- 연동 끊기: 회원·강사 누구든 `status:'ended'`로 바꿀 수 있다. 끊기면 이후 전송과 열람이 즉시 막힌다.

## 4. 화면

- **헤더 토글**(자격 있는 계정만): `내 기록 | 강사`. 강사 모드일 때 헤더 색이 다르고(보라 테두리) '강사 모드' 배지가 붙어 헷갈리지 않게 한다.
- **강사 모드 하단 메뉴**: `회원 · 수업 기록 · [＋수업 입력] · 템플릿 · 설정`. 내 기록용 메뉴는 숨긴다.
- **회원 목록**: 이름, 마지막 수업일, 이번 주 횟수, PT 남은 회차(§9-6), 연동 상태(대기·연동·끊김).
- **수업 입력**: 지금의 빠른 운동 입력을 그대로 재사용한다(대분류 → 종목 → 머신 → 세트). 맨 위에 '지난 수업 불러오기 / 템플릿 불러오기'가 있다.
  - 필라테스 강사는 시간 종목(수업 시간·형태·강도·메모)이 기본이다. 기구·동작 상세 기록 방식은 필라테스 자문 결과를 반영한다(별도 문서 `필라테스 기록 자문` 참고).
- **보내기 확인**: "○○님에게 오늘 수업(하체 · 5종목 18세트)을 보낼까요?" → 보냄 → 상태 추적.

## 6. 단계 계획
1. **3.2x.0 기반**: 강사 역할·승인, 연동(초대·수락·끊기), 규칙과 에뮬레이터 시험
2. **수업 보내기**: 강사 모드 토글, 회원 목록, 수업 입력 → 회원 검토함 → 확정
3. **템플릿**: 회원별 지난 수업·저장 루틴, 불러와 수정
4. **확장**(§8): PT 회차, 그룹 수업 일괄 전송, 회원 피드백, 강사 대시보드(동의 시)

## 7. 한계(미리 알아 둘 점)
- **푸시 알림**: 지금은 앱을 열어야 알림이 보인다(앱 안 알림). 휴대폰 푸시는 FCM이 필요하다. 보내는 서버는 Cloudflare 무료 서버로 할 수 있지만 Android 설정·권한 작업이 따로 든다. iPhone PWA 푸시는 제약이 크다.
- **실시간성**: 회원 화면은 동기화하거나 앱을 열 때 새 수업을 가져온다(실시간 리스너는 읽기 비용이 늘어 Spark 한도를 고려해야 함).
- **개인정보**: 건강 기록을 제3자(강사)와 나누는 일이다. 무엇을 공유하는지 명확한 동의, 언제든 철회, 끊으면 강사 열람 즉시 중단이 필수다. 강사가 가진 템플릿·메모를 회원 탈퇴 시 어떻게 할지 정해야 한다.
- **자격 확인**: 앱이 실제 자격증을 검증할 수는 없다. 관리자 승인은 '신뢰' 수준이다.
- **회원이 앱을 안 쓰는 경우**: 연동 전에는 보낼 곳이 없다. 강사 쪽에 '미연동 회원'으로 기록해 두고 연동 후 일괄 전송하는 기능이 필요할 수 있다(§9-4).

## 8. 발전 아이디어(제안)
- **PT 회차 관리**: 수업 확정 시 남은 회차 자동 차감, 10회 남음·만료일 알림. 강사·회원 모두에게 실용적이다.
- **회원 피드백 회신**: 확정할 때 '오늘 강도 1~10·불편했던 부위' 한 줄 → 강사에게 전달. 다음 수업 템플릿에 반영한다.
- **그룹 수업 일괄 전송**: 필라테스 그룹반은 한 번 입력해서 출석한 회원 여러 명에게 보낸다.
- **강사 대시보드(회원 동의 시)**: 회원별 주간 횟수, 부위 균형, 무게 진행. 'AI 코치'(프리미엄)와 엮으면 강사용 유료 플랜의 핵심이 된다.
- **수업 예약·출석**: 다음 수업 일정 → 회원에게 '예정' 기록(3.18.0 예정 기능 재사용)으로 미리 보이게.
- **센터 단위**: 한 센터에 여러 강사, 센터 관리자가 강사 승인. B2B 과금 모델로 이어진다.
- **회원이 고친 내용 알림**: 회원이 무게·횟수를 고쳐 확정하면 강사에게 '고침' 표시를 보여 준다(기록 정확도↑).

## 9. 대표님 확인 필요
1. 강사 자격: 관리자 승인만 할지, 자격증 사진 제출을 받을지
2. 연동 방식: 초대 코드(8자리) · 링크 · QR 중 무엇(복수 가능)
3. 강사가 회원 기록을 볼 수 있는 범위: 보낸 수업만 / 운동 전체 / 운동·식단·수치까지 회원이 골라서 동의
4. 앱을 안 쓰는 회원도 강사가 먼저 기록해 둘 수 있게 할지
5. 회원이 고친 뒤 확정하면 강사에게 알릴지
6. PT 남은 회차 관리를 처음부터 넣을지
7. 그룹 수업(한 번 입력 → 여러 회원) 지원 여부
8. 과금: 강사 모드 유료 여부(회원 수 제한 무료 + 유료 무제한 등)
9. 한 회원에게 강사 여러 명(PT + 필라테스) 허용 여부
