# 번핏 Pro 기능 조사와 마웨로그 구현 격차

> 이 격차표의 마웨로그 구현 판정은 **2026-10-31 초기 버전 기준**입니다. 2026-11-01 기능 확장 이후의 현재 상태는 [최신 구현 보고서](IMPLEMENTATION_REPORT_V2.md)를 확인하세요.

조사 기준일: 2026-10-31. 목적: 대표님의 개인용 마웨로그에 필요한 **동작과 데이터 구조**를 정하기 위한 기능 조사. 번핏의 화면·문구·에셋·비공개 로직을 복제한 명세가 아니다.

## 먼저 읽을 결론

- **현재 마웨로그의 식단·운동 입력은 수동 기록의 최소 흐름이다. 번핏과 같은 입력 경험이나 Pro 전체 기능이 아니다.**
- 공식 공개 자료로 확인한 기능은 아래에 적었다. 메뉴 위치, 탭 순서, 팝업, 음식 검색 결과, 비공개 계산식처럼 공개되지 않은 조작 세부는 **미확인**으로 둔다. 대표님이 제공한 Pro 혜택 화면은 그 시점의 표시를 보여주지만, 모든 최신 기능의 경계까지 확정하지는 않는다.
- 아래 `반영됨`은 **코드에 경로가 있다는 뜻**이다. Android 에뮬레이터에서는 홈·몸·운동 화면 이동만 확인했다. 식단·운동 입력의 기기 내 저장·재진입은 아직 실사용 검증 전이다.
- `반영됨`은 코드에 기능 경로가 있다는 뜻이며, 식단·운동 입력의 기기 내 완결 검사는 아직 전이다. `반영됨(일부)`는 적힌 범위만 코드에 있고 나머지는 `가능·미구현`이다. `가능·미구현`에는 모델/API·서버 연동이 필요한 기능과 대표님이 보류한 워치도 포함한다. `반영 불가`는 번핏의 독점 코드·에셋·비공개 산식을 그대로 확보하거나 공개 자료만으로 전체 Pro 화면을 완전히 확정하는 일에 한정한다.

## 1. 식단: 어떻게 입력하고 무엇을 보나

공개 자료가 뒷받침하는 **입력 경로**는 수동 음식 기록, 음식 사진을 찍는 AI 렌즈, 먹은 음식의 자연어 설명을 넣는 AI 텍스트다. 식사·간식·보충제·단백질 섭취를 날짜별로 다루며, 섭취 칼로리와 탄수화물·단백질·지방을 확인한다. 사진·텍스트 결과의 **확인/수정 화면, 분량 단위, 식품 검색 DB, 바코드, 자동 영양값의 출처는 확인되지 않았다.** [S1](https://play.google.com/store/apps/details?id=com.bunnit.haja.android&hl=ko) · [S2](https://apps.apple.com/kr/app/id1503464984) · [S3](https://burnfit.io/article/hevy-vs-burnfit-%EB%82%98%EC%97%90%EA%B2%8C-%EB%A7%9E%EB%8A%94-%EC%9A%B4%EB%8F%99-%EA%B8%B0%EB%A1%9D-%EC%95%B1/)

| 기능/입력 단계 | 번핏에서 공개 확인된 동작·추적값 | Pro | 마웨로그 판정과 정확한 차이 |
|---|---|---|---|
| 날짜·끼니 단위 수동 기록 | 음식/식사·간식·보충제·프로틴 기록 | F(S3) | **반영됨(코드 구현·기기 입력 미검증)**: 날짜, 아침·점심·저녁·간식, 자유 입력 음식명. 보충제·프로틴 전용 분류는 없음 |

**현재 마웨로그 실제 입력 순서:** `식단 → ＋식사 → 날짜/끼니 선택 → 음식명·kcal·탄단지 숫자 직접 입력 → 저장 → 해당 날짜 총합/끼니 목록`. 식품 검색·사진 인식·자동 영양값·수량/분량 입력은 없다. 입력값을 직접 알아야 한다. 코드: `app/app.js`의 `modalHTML`, `foodPage`; `domain.js`의 `cleanMeal`, `mealTotals`.

## 2. 운동: 어떻게 시작·입력·추적·제안하나

## 반영 불가와 외부 연동이 필요한 기능의 구분

1. **번핏과 픽셀 단위 동일 화면, 독점 이미지/GIF, 내부 코드·비공개 계산식·동일 음식 DB 확보:** 공개 자료로 확인할 수 없고, 권리·약관 검토 없이 가져오는 방식은 채택하지 않는다. 같은 목적을 달성하는 **자체 설계**는 가능하다.
2. **실제 생성형 AI 결과:** `가능·미구현`이다. 모델/API 또는 기기 내 모델·비용·사진 처리 정책이 없으므로 현재 앱에서 작동하지 않는다. `ai-adapter.js`는 데이터 형식과 연결 자리만 준비했다.
3. **워치/서버 연동:** `가능·미구현`이다. 대표님의 보류 결정 또는 서비스 계정·기기별 API/권한이 없어 현재 제공하지 않는다.
4. **번핏 Pro 100% 완전 목록·입력 화면 재현:** 공개 설명은 모든 설정과 변경 이력을 제공하지 않는다. 실제 Pro 사용 화면을 합법적으로 관찰해 단계별 화면 기록을 추가하기 전에는 '완전'이라고 표시할 수 없다.

## 구현 우선순위 제안 — 아직 작업하지 않음

1. **입력 신뢰성:** Android 에뮬레이터와 실기기에서 운동·식단 입력 → 저장 → 재진입 → 수정/삭제 → 백업·복원 검증. 현재는 수정 UI 자체가 없다.
2. **식단 사용성:** 자주 먹는 음식·분량/단위·보충제 분류·탄단지 자동 계산, 7/30일 매크로 그래프.
3. **운동 사용성:** 종목 카탈로그/검색, 직전 세트 병치, 세트 복사, 휴식 타이머, 루틴 편집/삭제, 유산소 입력. 세트 완료 체크는 마웨로그 자체 개선 후보이며 번핏 제공 여부 미확인.
4. **분석:** 운동별 시계열·전월 비교, 부위별 세트/볼륨, 계산 근거가 보이는 피로도·회복 지표, 월간 보고.
5. **연결 기능:** AI 사진/텍스트·데일리/주간 제안과 서버 동기화는 독립 모듈로 붙이고, 출력 검토·수정 단계를 반드시 둔다. 워치는 계속 보류.

이번 조사는 공식 공개 페이지와 대표님 제공 이미지, 마웨로그 코드에 한정했다. 번핏 Pro 계정의 실제 조작, 구매 화면의 최신 요금제별 권한, 음식 데이터 출처, 모든 화면·알고리즘은 직접 검증하지 않았다. 따라서 `?` 표시는 추후 실제 앱 화면으로 확인해야 한다.
