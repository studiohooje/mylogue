# 4.1.1 작업로그 — 초안 기록 문서가 이미 있을 때 확정 막힘

작성 2026-11-21 · Claude

## 요청
대표님: 4.1.0에서 다시 확정 → "같은 AI 초안의 기록이 이미 있습니다. 목록을 새로고침해 주세요." 화면에는 그런 기록이 없음.

## 원인
- AI 초안 확정은 기록 문서 ID를 `ai-<초안ID>-n`으로 만들고, 거래(transaction) 안에서 그 문서가 하나라도 **존재하면** 막았다. 존재 여부만 보았기 때문에 지워진 기록의 자리(payload null, 동기화의 삭제 표시)나 화면에 안 보이는 옛 문서가 있어도 막혔다. 대표님 계정 데이터는 직접 보지 않았다(내장 브라우저는 로그인 안 됨) → 정확히 어느 경우인지는 미확인.

## 바꾼 것
- `ai-drafts.js` `recordWritePlan`: 문서가 이미 있으면 다음 revision으로 이 초안 내용을 다시 쓴다(문서 ID가 초안 전용이라 중복이 생기지 않음). 보안 규칙(update는 revision+1)을 그대로 따른다.
- 시험: `tests/v401.test.js`에 revision 계획, `tests/record-rewrite-rules.test.js`(에뮬레이터: 지워진 자리를 revision+1로 다시 쓰기 허용, revision 1로 덮어쓰기는 거부) 통과.
