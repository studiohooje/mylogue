# 마이로그 보안 점검 (출시 전 집중 점검)

> 2026-11-22. 2·3번은 점검 직후 고쳤다(앱 4.7.0, agent-bridge). 범위를 정해 소스 코드를 직접 읽은 **집중 점검**이다. security-audit 스킬의 '전체 감사 모드'(여러 에이전트 6단계·검증기 실행)는 돌리지 않았다. 실제 서버·계정·기기에 공격 시험을 하지 않았고, 아래 내용은 코드 근거와 판단이다. 코드는 고치지 않았다.

## 범위

| 대상 | 본 것 |
|---|---|
| `app/firestore.rules` (269줄) | 계정 승인, 기록(records), AI 초안, 코치 연동(invites·links·sessionAcks), 공용 도감, 인기 순위(popularity), 등록 요청 |
| `app/storage.rules` | 등록 요청 사진 |
| `agent-bridge/` | 로컬 MCP 서버의 접속 허용 범위(Origin)·페어링·토큰 보관 |
| `app/android/.../MainActivity.java` | 다른 앱에서 들어오는 공유(글·사진)와 앱 바로가기 |

보지 않은 것: 앱 전체의 화면 출력(XSS 전수), 결제·코치 화면 실제 흐름, 배포 서버 설정(GitHub Pages 헤더), Firebase 콘솔 설정(승인된 도메인·API 키 제한).

## 결론 한 줄

**다른 사람의 기록을 읽거나 바꿀 수 있는 구멍은 찾지 못했다.** 기록·AI 초안은 "본인 + 관리자 승인" 규칙으로 잘 막혀 있고, 규칙마다 필드·크기·시각 검사가 있다. 고치면 좋은 곳 3개(낮음)와 확인이 필요한 곳 3개가 있다.

## 고치면 좋은 것

### 1. [낮음] 인기 순위(popularity)에 승인된 사용자가 아무 이름이나 올리고 숫자를 키울 수 있음
- 근거: `firestore.rules` `match /popularity/{kind}/items/{itemId}` — 승인된 사용자는 누구나 `name`(최대 120자)으로 새 항목을 만들고, `count`를 1씩 무한히 올릴 수 있다. 이 목록은 다른 승인 사용자 모두가 읽는다(추천 순서에 쓰임).
- 결과: 한 사용자가 부적절한 이름의 음식·운동을 만들어 숫자를 올리면 다른 사람의 추천 목록 위쪽에 보일 수 있다(화면 출력은 이스케이프되어 스크립트 실행은 아님). 사용자를 수동 승인하는 지금은 위험이 낮다.
- 가장 작은 수정: 인기 항목 문서 ID를 공용 도감 ID로만 허용(`exists(/catalog/...)`)하거나, 사용자별 하루 증가 한도(사용자별 하위 문서)를 둔다. 추천에 쓸 때 공용 도감에 없는 이름은 거른다.

### 2. [낮음] 사진 공유 받기에서 `file://` 주소를 거르지 않음 — **같은 날 고침**(content:// 이미지만 받음)
- 근거: `MainActivity.deliverImage` — `EXTRA_STREAM`의 URI를 종류 확인 없이 `openInputStream`으로 연다.
- 결과: 다른 앱이 `file://`로 마이로그 앱 내부 파일 경로를 넘기면 그 내용을 읽어 화면 미리보기에 올릴 수 있다. 다만 결과는 그 사용자 자신의 화면에만 보이고 밖으로 보내는 경로가 없어 피해는 작다.
- 가장 작은 수정: `"content".equals(uri.getScheme())`일 때만 읽고, `getType()`이 `image/`로 시작하는지 다시 확인한다.

### 3. [낮음] 로컬 AI 연결 서버가 `http://localhost`(포트 없음) 출처도 허용 — **같은 날 고침**(목록에서 뺌)
- 근거: `agent-bridge/mcp.mjs:13` 허용 출처 목록.
- 결과: 같은 PC의 80·443 포트에서 도는 다른 웹 페이지가 `/unpair`를 불러 연결을 끊을 수 있다(연결 정보 탈취는 불가 — `/pair`는 사용자의 Firebase 토큰 검증이 필요). 불편을 주는 정도다.
- 가장 작은 수정: 안드로이드 앱이 실제로 쓰는 출처만 남기고(`https://localhost`가 Capacitor 기본이면 그것만), `/unpair`도 페어링 때 받은 값으로 확인한다.

## 확인이 필요한 것 (코드 밖 설정)

1. **Firebase 콘솔의 승인된 도메인**에 `studiohooje.github.io`와 앱 출처만 있는지.
2. **Firebase API 키 제한**(Google Cloud 콘솔): 웹 키에 HTTP 리퍼러 제한, 안드로이드 키에 패키지·서명 제한이 걸려 있는지. 코드에 키가 들어 있는 건 Firebase의 정상 방식이지만 제한은 콘솔에서만 확인된다.
3. **AI 연결 토큰 보관 파일**(`agent-bridge/store.mjs`): 새로 고침 토큰을 사용자 폴더의 일반 파일로 저장한다. 같은 PC의 같은 사용자 권한이면 읽을 수 있다. 공용 PC에서는 연결 해제를 안내하는 문구가 있으면 좋다.

## 잘 되어 있던 것

- 기록(`records`)은 본인 + 승인만, `revision`이 정확히 1씩 올라가야 쓰기 가능, 지우기는 빈 값으로만(직접 삭제 금지).
- AI 초안은 본인만 만들고 처리. 코치는 자기가 보낸 운동 초안만, 연동이 살아 있을 때만 만든다.
- 사용자 문서는 스스로 `pending`으로만 만들 수 있고 승인은 관리자만.
- 관리자 판별은 UID 또는 **인증된 이메일**(`email_verified == true`)로만.
- 공유받은 글·사진은 `JSONObject.quote`로 감싸 웹뷰에 넘겨 스크립트 주입이 막혀 있다. 바로가기 종류는 `body|meal|workout`만 받는다.
- 로컬 AI 서버는 `127.0.0.1`에만 열리고, 출처가 없거나 목록 밖이면 403.
