# 마웨로그 기록 경험 재설계 제안

작성: 2026-11-07 · 상태: 기획안, 미구현 · 대상: 동일한 웹/PWA 및 Android 앱 UI

## 목표와 현재 문제

모토는 **“오늘을 기록으로 바꿔.”**이다. 사용자가 기록을 시작하고 반복하는 데 드는 결정을 줄이고, 실제 기록이 쌓이는 감각을 첫 화면에서 보여준다. 현행 `app/ui-helpers.js`의 식단 폼은 날짜·끼니·음식명·수량·단위·열량·탄단지·출처·메모를 한 번에 보여 준다. **필수 입력은 날짜와 음식명뿐**이지만, 선택 필드가 처음부터 모두 보인다. 운동 폼은 날짜·제목·컨디션·수면·에너지·근육통·통증·도감·장비·세트 상세가 같은 흐름에 있다. 최근 음식 칩, 지난 세트 적용, 임시 저장·복구, 되돌리기는 이미 구현되어 있으나 주 동선에서 찾고 쓰기 어렵다. `app/app.js`의 홈은 체중·칼로리·근육량·운동량 카드 4개가 기록 행동보다 먼저 보인다.

## 새로운 기록 구조

**먼저 남기고, 필요할 때 자세히.** 빠른 입력과 정밀 입력은 같은 기록을 공유한다. 빈 값은 0으로 만들지 않고 `미입력`·`부분 기록`·`추정`을 명확히 표시한다.

| 현재 | 제안 | 사용자가 체감할 변화 |
|---|---|---|
| 식단 긴 폼 | 최근 음식·즐겨찾기·자주 먹는 **한 끼 조합** 카드 → 양 `½ / 1 / 1½ / 2` 선택 → 저장 | 반복 식사를 다시 계산하지 않음 |
| 새 음식의 선택 입력 필드가 처음부터 모두 노출 | 이름만으로도 부분 기록 → 열량·탄단지·출처는 필요할 때 펼쳐 보강 | 불완전해도 기록 습관을 이어감 |
| 종목·세트 긴 폼 | `지난 운동 이어하기 / 내 루틴 / 부위에서 고르기` → 지난 중량·횟수·kg/lb·머신을 채운 카드 | 같은 운동을 매번 다시 구성하지 않음 |
| 세트마다 여러 입력 | 실제 수행 후 큰 `세트 완료` 버튼 1회; 다를 때만 중량·횟수 조절 | 운동 중 화면을 보는 시간을 줄임 |
| 세부 옵션 상시 노출 | RPE·세트 유형·슈퍼세트·머신 교체는 상세 패널 | 기본 흐름에 필요한 조작만 남음 |
| 임시 저장·복구·되돌리기가 숨은 보조 기능 | 홈에서 `이어하기`를 노출하고 세트 직후 취소와 종료 요약을 선명하게 표시 | 통화·앱 종료 후에도 복구 동선을 쉽게 찾음 |

식단 사진·음성·외부 AI는 후속 **선택적 입력 경로**로만 설계한다. 추정 영양값은 사용자가 검토하기 전 확정하지 않는다. 상품 바코드는 식품 데이터베이스와 출처 관리가 준비되기 전까지 약속하지 않는다. 친구 등 제3자의 건강 기록을 외부 AI/API로 보내는 기능은 전송 전에 당사자 승인, 처리 범위, 제공자, 보관과 국외 이전 여부를 별도로 확인한다.

## 첫 화면과 동기부여

기존 4개 지표 카드보다 **오늘의 점화** 히어로를 먼저 놓는다. 딥 네이비 `#07111E` 위 전기 파랑 `#3B8DFF`의 빛/그라데이션, 큰 Pretendard 제목, 실제 기록 한 가지를 크게 보여 준다. 주 버튼은 상황에 따라 `식사 기록` 또는 `지난 운동 이어하기`; 그 아래에 최근 음식·운동의 한 번 선택 카드를 둔다. 지표 차트는 그다음이다.

고정 브랜드 문구: **오늘을 기록으로 바꿔.** 짧은 변주: **말보다 기록. / 한 세트부터. / 지금, 하나만. / 흐름은 쌓인다.** 명령형 카피는 행동을 선명하게 만들되 체형 평가·벌칙·연속일 상실 압박은 쓰지 않는다.

| 상태 | 첫 문구 | 주 행동 |
|---|---|---|
| 오늘 미기록 | 오늘을 기록으로 바꿔. | 식사 또는 운동 첫 기록 |
| 식단 일부 | 첫 기록 완료. 다음 한 끼도 가볍게. | 최근 식사 재사용 |
| 운동 중 | 지금 쌓는 중. | 다음 세트 완료 |
| 운동 완료 | 오늘의 세트, 기록됨. | 결과 보기 |
| 계획한 휴식 | 회복도 계획의 일부. | 휴식 확인 또는 식단 기록 |
| 며칠 공백 | 다시 한 번이면 이어집니다. | 작은 기록 시작 |
| 통증·낮은 컨디션 | 오늘은 강도보다 상태를 먼저. | 상태 확인; 증량 제안 숨김 |

문구는 날짜와 기록 상태에 따라 하루 동안 안정적으로 정하고 직전 3개 노출 문구와 중복을 피한다. 재렌더마다 무작위 변경하지 않는다. 히어로 진입과 기록 직후에만 짧은 페이드·숫자 변화·푸른 펄스를 사용한다. 반복 점멸은 쓰지 않고 `prefers-reduced-motion`에서는 정적으로 표시한다. 기록이 없으면 `0회` 성과 대신 `시작 전`으로 표시한다.

## 구현 단위와 검증

1. 현행 입력 동선 기준선 수집, 홈·식단·운동의 저충실도 화면 2안 비교.
2. 기존 최근 음식 칩을 주 동선으로 올린 식단 빠른 기록, 한 끼 조합, 부분 기록 상태 및 상세 보강.
3. 기존 지난 세트 적용·임시 저장·되돌리기를 주 동선에 연결한 운동 실시간 세트와 종료 요약.
4. 상황별 히어로, 문구 로테이션, 모션 및 접근성.
5. Android/PWA 같은 UI 소스에서 휴대폰 화면·오프라인·기존 기록 이전·kg/lb·동기화 충돌·화면 읽기·동작 줄이기 검증.

설계 목표(아직 실측 성과 아님): 반복 식단 3탭 이내, 기본 세트 완료 1탭, 임시 기록 유실 0건, 미입력 영양값을 0g 또는 완료로 오인시키는 화면 0개. **새 계획 세트와 복사한 미수행 세트는 기본 미완료**이며, 볼륨·피로도·완료 통계에는 실제 완료한 세트만 넣는다. 현행 `workoutFormHTML`은 `completed`가 명시적 `false`가 아니면 체크되는 부분이 있어 구현 시 반드시 바로잡는다. 측정할 값: 기록 시작→완료율, 중도 이탈 지점, 기록 소요 시간, 7/28일 자발적 기록일, 수정·누락률, 히어로 CTA 사용률. 초기 측정은 **기기 안에서만 집계**하고 외부 분석 전송은 별도 동의와 설계 검토 후 결정한다. 알림은 기본 강제가 아니라 선택사항이다.
