# 마웨로그 Beta 2.0.0 재검토

> 2026-11-19 후속: 아래는 당시 발견한 결함 목록이다. 구현·배포로 해결한 범위와 남은 실제 계정 시험은 [Beta 2.0.1 배포 기록](releases/2.0.1.md)을 우선 확인한다. 항목 2·3·4·5·6·8은 코드와 자동 시험에서 보완했다. 항목 1·7·9의 실계정/실기기/API 경계는 남아 있다. 항목 10의 발표 자료는 화면·획득 경로·비용 가설을 보완했지만 검증 수치는 내부 시험 후 채워야 한다.

2026-11-18 기준. 공개 배포와 APK 제작은 확인했다. 아래는 **구현·검증 완료 판정을 보류해야 하는 항목**이다. 이 문서는 다음 패치의 작업 목록이며 기능 완료 증명서가 아니다.

## P0 · 실제 사용 전 확인·수정

1. **두 사용자 실제 연결 시험 없음.** 로컬 MCP 짝짓기, Firebase 실계정 승인, AI 검색·초안 생성, 웹/Android 검토·확정, 다른 계정에서 보이지 않는지까지 한 번에 실행한 증거가 없다. 자동 시험은 도구 단위와 Firestore 에뮬레이터다. 대표님과 친구분이 각자 본인 계정으로 시험해야 한다.
2. **중복 방지는 요청 ID 재시도에만 확실하다.** `agent-bridge/firebase.mjs`의 `draftId(uid,requestId)`는 같은 요청 ID를 재사용할 때만 같은 초안이다. `app/ai-inbox.js`의 기존 기록은 경고만 보여주고 확정은 허용한다. 같은 식사·머신을 새 요청 ID로 다시 보내면 중복 가능하다. 검색도 사용자 기록 최대 1,500건, 공용 도감 종류당 500건이다.
3. **AI 검토함에서 모든 핵심 필드를 수정할 수 없다.** 식단은 음식명·양·영양값만 바꾸고 날짜·식사 번호·시각은 바꾸지 못한다. 운동은 날짜·제목·중량·단위·횟수만 바꾸고 종목명·머신·세트 수·세트 완료 시각·부위는 바꾸지 못한다. 새 운동의 주·보조 근육도 화면에서 확인·편집할 수 없다. `app/ai-inbox.js`의 `mealEditor`, `workoutEditor`, `catalogEditor`, `readAIReview`를 보완해야 한다.
4. **영양 추정 범위가 수정 후 낡을 수 있다.** 사용자가 검토함에서 중심 칼로리·탄단지를 고쳐도 기존 `aiEstimate` 범위는 그대로 확정된다. 범위 자체를 수정하거나 변경값에 맞춰 추정 표시를 재검토하게 해야 한다. 새 음식 프리셋은 `cleanFoodPreset`에서 추정 메타데이터가 보존되지 않는다.

## P1 · 약속한 경험과 다른 부분

5. **머신 사진 등록은 앱에서 작동하지 않는다.** 공용 등록 요청 화면의 사진 선택지는 비활성화되어 있다(`app/app.js`의 `catalogRequestHTML`, `app/catalog-cloud.js`의 `submitCatalogRequest`). AI 대화에서 사진 두 장을 받은 뒤 도구에는 `whole`·`nameplate`라는 역할 문자열만 보낸다. 실제 사진 두 장이 있었는지, 명판이 읽혔는지를 서버가 검증하지 않으며 원본도 보관하지 않는다. 이번 Spark 설계의 의도적 범위 제한이지만 “사진 등록 완성”으로 설명하면 틀리다.
6. **머신 별칭과 도감 연결이 AI 입력에서 완전히 자동화되지 않았다.** 검색 결과에 개인 머신은 나오지만 별도 별칭 배열은 `cleanMachine`의 저장 구조에 없다. AI가 이름·제조사·모델로 재검색하는 수준이다. 검색 결과를 기존 운동 세트의 `machineId`에 정확히 넣는 실제 사용자 시험도 없다.
7. **모바일에서 AI에게 바로 말하고 사진 보내는 최종 흐름은 아직 아니다.** 현재 로컬 MCP 연결은 AI 도구와 마웨로그 웹을 같은 컴퓨터에서 열어야 한다. 휴대전화의 일반 ChatGPT 대화나 Android 앱 단독으로 초안을 직접 쓰지 못한다. 앱 내 AI API는 의도대로 보류된 상태다.
8. **근거·출처가 최종 기록에 남는 범위가 제한적이다.** 초안의 `evidence`에는 출처를 넣을 수 있지만, 확정된 식단·음식 기록에 출처 URL·제품 기준량이 구조화되어 보존되지 않는다. 나중에 영양값을 검증하거나 정정하기 어렵다.
9. **APK는 디버그 빌드다.** Android 에뮬레이터 실행과 공개 다운로드는 확인했다. 실기기 설치·업데이트, 다른 서명 키로 빌드한 다음 버전의 설치, 친구 기기 사용은 시험하지 않았다. 정식 배포에는 고정된 릴리스 서명과 업그레이드 시험이 필요하다.
10. **사업계획서의 투자 발표 품질은 추가 보완이 필요하다.** 실제 화면과 예시 화면 구분, SWOT·수익 가설은 담았다. 현재 PPTX의 제품 캡처는 슬라이드에서 작아 읽기 어렵고, 경쟁 우위의 검증 자료·초기 고객 확보 경로·비용 민감도·실험 결과가 없다. 투자용 최종본이라고 부르기보다 전략 초안이다.

## 유지할 검증 결과

- 웹 Beta 2.0.0과 APK 링크의 공개 HTTP 응답 및 GitHub Actions 성공.
- 앱 자동 시험 107건 중 106건 통과, 일반 실행에서 건너뛴 Firestore 권한 시험은 에뮬레이터에서 별도 통과. 연결 도구 시험 7건 통과.
- Android 에뮬레이터의 홈·검토함·설정 화면과 390/768/1200px의 예시 화면 레이아웃 확인.

## 다음 실행 순서

1. 실제 승인 계정 1개로 로컬 연결·식단 사진 추정·운동·인바디·확정까지 수행한다. 이어 친구 계정에서 같은 경로와 교차 접근 차단을 확인한다.
2. 확인된 장애를 고치고, 검토함의 날짜·시각·종목·머신·세트·추정 범위 편집과 내용 기반 중복 차단을 구현한다.
3. 사진 기반 머신 등록의 범위를 정한다. 현재 설계라면 AI 대화의 사진 판정만 사용한다고 UI와 문서에 일치시킨다. 앱 내부 사진 요청을 제공하려면 저장·검증 흐름을 별도로 구현한다.
4. APK 실기기 설치·업데이트 시험, 프롬프트의 Codex·Claude Code 각각의 실제 도구 호출 시험, 사업계획서의 화면 가독성·증거 보강을 한다.
5. 사용자에게 보이는 수정은 `2.0.1` 패치로 버전·패치노트·웹·APK를 함께 갱신한다.
