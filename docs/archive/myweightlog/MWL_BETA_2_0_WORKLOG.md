## 사용자 승인과 최종 목표

2026-11-17 대표님이 기획, 구현, 검증, 웹·Android 배포, 문서 완성까지 승인했다. 최초 시험은 대표님과 친구 등 2~3명이 각자의 마웨로그 계정과 각자의 Codex/Claude Code 등 AI를 사용한다. 마웨로그 내부 AI API 연결은 이번 시험 범위가 아니다. 사용자가 사진 또는 자연어를 AI에 보내면 AI가 계정별 기존 음식·운동·머신을 조회하고 **직접 검토함 초안으로 입력**한다. 사용자가 수정·확정한 뒤 기록이 된다. 파일을 사람이 옮기는 흐름은 대체 경로다. 나중에는 앱·웹 내부 AI가 같은 계약을 사용한다.

음식 사진으로 양을 모르면 합리적으로 추정하여 `약 650 kcal`처럼 표시하고, 탭·호버에서 추정 범위를 보여준다. 사용자가 밝힌 양은 우선한다. 머신 최초 식별은 전체 사진과 제조사·모델 명판 사진 최소 2장이 기본이다. 명확하지 않으면 브랜드·모델을 묻고 임의 확정하지 않는다. 인바디는 앱 다운로드 결과표나 인쇄물 사진의 보이는 수치를 읽고 검토한다. 사용자별 머신 별칭을 영속 저장한다. 기존 항목 검색과 중복 방지가 필수다. Codex 전용이 아닌 모델 공통 프롬프트 MD를 **구현 후 실제 계약에 맞춰** 완성한다.

3. 사용자 2계정 시험 가능 수준의 기능·보안·회귀·화면 검증, APK 빌드와 GitHub Pages 배포.
4. 실제 도구로 검증한 Codex/Claude Code 공통 프롬프트·연결 지침 MD.
5. 구현된 화면 캡처와 미래 기능을 명확히 구분한 투자 발표 수준의 사업계획서. SWOT·서비스 방향·차별화·사업 모델·로드맵 포함. 법률 문구는 해당 문서에 넣지 않는다. 검증되지 않은 지표·매출 수치는 창작하지 않는다.
6. 모든 배포마다 버전별 패치노트 파일. 이번은 `MWL Beta 2.0.0`; 이후 기능은 2.1.0, 수정은 2.0.1 방식.

## 재개 시 먼저 할 일

1. 이 파일과 사용자의 최신 메시지 및 `app/firestore.rules`, `app/cloud-sync.js`, `app/cloud-model.js`, `app/domain.js`, `app/app.js`, `app/catalog-cloud.js`, `app/ai-adapter.js`를 확인한다.
2. `git ... status --short`로 checkout 상태를 확인한다. 기존 사용자 작업을 덮어쓰지 않는다.
3. 연구·기획 결과를 받아 기능 범위를 확정하고 본 로그를 갱신한다.
4. 구현은 한 기능 단위씩 테스트하고 체크리스트에 완료 증거를 남긴다. 테스트하지 않은 기능을 완료라 하지 않는다.
5. 공개 배포는 소스→public-release 복사, 공개 checkout 테스트·빌드, commit/push, Actions success, 공개 사이트 확인 순서다. Android는 `build-android.ps1`, APK 설치·에뮬레이터 화면 검증.

## 확인할 제약

GitHub Pages는 정적 호스팅이다. 외부 AI 도구의 사용자별 인증·서버 쓰기 경로는 별도 설계가 필요하다. Firebase Spark를 Blaze로 바꾸지 않기로 한 이전 결정을 유지한다. 실물 사용자 계정 2개와 실제 사진 테스트는 사용자 정보가 제공된 범위 안에서만 할 수 있다. 불가한 것은 명시하고 가능한 범위의 대안을 구현한다.
