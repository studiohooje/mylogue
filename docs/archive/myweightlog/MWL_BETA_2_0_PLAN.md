# MWL Beta 2.0.0 기준서

작성 기준: 2026-11-17 대표님과 확정한 최종 방향. 작업 상태는 `MWL_BETA_2_0_WORKLOG.md`에서 추적한다.

## 제품 목표

기록하고 싶어지는 건강·운동 일지. 사용자는 직접 빠르게 입력할 수도 있고, 자신이 사용하는 Codex·Claude Code 등 AI에게 사진과 자연어를 보내 기록 초안을 맡길 수도 있다. 초기 시험에서는 AI 모델 API를 마웨로그 앱 안에 연결하지 않는다. 각 사용자의 AI가 각 사용자의 마웨로그 계정에 인증된 도구로 접속하여 **검토함 초안만** 작성한다. 사용자가 검토·수정·확정한다. 미래의 앱 내부 AI도 동일한 검토·저장 계약을 재사용한다.

## 사용자 여정

1. 승인된 각 사용자(대표님·친구)가 본인 계정으로 로그인한다.
2. 사용자 컴퓨터에서 로컬 AI 도구를 실행하고 마웨로그 앱에서 일회성 짝짓기를 한다. 인증값은 프롬프트·소스·Git에 넣지 않는다.
3. AI에 자연어·사진을 준다. AI는 자신의 대화에서 사진을 읽고 필요하면 출처를 검색하며, 마웨로그 도구로 **해당 사용자 계정**의 기존 음식·운동·머신을 찾는다.
4. 충분히 식별되면 초안을 검토함에 저장한다. 음식량을 모르면 중앙 추정값·범위·근거·추정 표시를 함께 남긴다. 사용자 제공량이 우선이다. 머신 최초 식별은 전체·명판 최소 두 사진을 요청하고 불명확하면 브랜드·모델을 질문한다. 인바디 결과표에서 판독 불가 수치는 비워 둔다.
5. 사용자는 웹·Android의 검토함에서 원문, 해석값, 중복 후보, 추정 근거를 보고 수정·확정·반려한다. 확정된 기록만 일반 타임라인과 분석에 반영한다.

## 데이터·권한 원칙

- Firestore `users/{uid}/aiDrafts/{draftId}`: 로그인한 승인 사용자만 자신의 초안을 조회·생성·검토한다. 관리자도 타인의 건강 초안에 자동 접근하지 않는다.
- `id`, `requestId`, `type`, `status`, `schemaVersion`, `sourceModel`, `originalUtterance`, `parsedData`, `uncertainty`, `evidence`, `createdAt`, `updatedAt`을 기본 계약으로 한다. 생성 재시도 시 같은 요청 ID를 사용한다.
- 초안 확정은 기존 `cleanBody`, `cleanMeal`, `cleanWorkout` 검증을 통과해야 한다. 기록 ID는 초안 ID와 연결해 재확정 중복을 막는다.
- 사진 원본 서버 보관은 이번 Spark 시험에 포함하지 않는다. AI 대화에 첨부한 사진에서 추출한 사실·근거 메타데이터만 초안에 보관한다. 앱에서 로컬 보관하는 사진과 원격 초안의 관계를 분명히 표시한다.
- 공용 음식·머신 도감의 공개 등록은 기존 관리자 검토 절차를 따른다. 개인 기록/별칭은 각자의 계정에 저장된다.

## 검증 범위

- 기록 종류별 정상·오류·중복·재시도·계정 교차 접근 거절 시험.
- 390px·768px·1200px의 한국어 줄바꿈, 버튼·카드 간격, 탭/호버의 추정 범위 표시.
- Android 에뮬레이터 설치·입력·검토·확정. 실사용 친구 계정 시험은 친구 본인이 접속할 때만 완료로 표시한다.
- 웹과 APK에 동일한 `2.0.0` 버전 표기, 패치노트, 테스트·빌드·배포 결과 기록.

## 후속 단계

공통 입력 도구가 실제 동작한 뒤 Codex·Claude Code 공통 프롬프트 MD를 작성한다. 투자 발표형 사업계획서는 V2.0 실제 화면과 미래 목업을 구별하고 SWOT·사업 모델·검증 지표를 담되 법률 문구나 창작한 시장·매출 수치를 넣지 않는다.
